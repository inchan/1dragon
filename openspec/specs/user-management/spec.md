## Requirements
### Requirement: Social login authentication
The system SHALL support social login via Kakao (primary for Korean market), Google, and Apple. Authentication MUST be implemented using Better Auth with Hono integration. No email/password registration in MVP. The system MUST handle same-email across different social providers by linking accounts.

#### Scenario: Kakao login
- **WHEN** a user clicks "카카오로 시작하기"
- **THEN** the Kakao OAuth flow initiates, and upon successful authentication, a user account is created (first time) or session is established (returning user)

#### Scenario: Google login
- **WHEN** a user clicks "Google로 시작하기"
- **THEN** the Google OAuth flow initiates and the user is authenticated

#### Scenario: Apple login
- **WHEN** a user clicks "Apple로 시작하기"
- **THEN** the Apple Sign In flow initiates and the user is authenticated

#### Scenario: Same email different provider
- **WHEN** a user who registered via Kakao tries to login via Google with the same email
- **THEN** the system shows "이미 카카오로 가입된 이메일입니다. 카카오로 로그인하거나 계정을 연결하세요" with an account linking option

#### Scenario: Account linking
- **WHEN** a user chooses to link a new social provider to their existing account
- **THEN** both social providers are linked and either can be used for future login

### Requirement: User profile management
The system SHALL store minimal user profile information. Required: email (auto-collected from social login). Optional (collected during onboarding): business_name, selling_platform (Enum: SmartStore/Coupang/Cafe24/Other), product_category. Profile MUST be editable after creation.

#### Scenario: Profile creation on first login
- **WHEN** a user completes social login for the first time
- **THEN** a user record is created with email from the social provider and default Free plan

#### Scenario: Onboarding survey
- **WHEN** a new user logs in for the first time
- **THEN** an optional onboarding flow asks for business_name, selling_platform, and product_category (skippable)

#### Scenario: Profile update
- **WHEN** a user navigates to profile settings and updates their business name
- **THEN** the profile is updated and the change is reflected immediately

---

### Requirement: Session management
The system SHALL manage sessions using Better Auth's session system with refresh tokens. Sessions MUST auto-refresh when active. Session expiry MUST be 30 days for refresh tokens and 15 minutes for access tokens. Concurrent sessions across devices MUST be allowed.

#### Scenario: Session auto-refresh
- **WHEN** an access token expires while the user has a valid refresh token
- **THEN** a new access token is issued transparently without requiring re-login

#### Scenario: Session expiry
- **WHEN** a refresh token expires (30 days of inactivity)
- **THEN** the user is redirected to the login page with message "세션이 만료되었습니다. 다시 로그인해주세요"

#### Scenario: Concurrent sessions
- **WHEN** a user logs in from both mobile and desktop browsers
- **THEN** both sessions are maintained independently

### Requirement: Video generation history
The system SHALL maintain a history of all videos generated by the user. History MUST be accessible from the dashboard and display: thumbnail, product name, generation date, status (succeeded/failed), style used. History MUST be paginated (20 items per page) and sorted by creation date (newest first). Re-download of past videos MUST be available for 30 days.

#### Scenario: View generation history
- **WHEN** a user navigates to the dashboard
- **THEN** a list of generated videos is displayed with thumbnails, sorted newest first

#### Scenario: Re-download past video
- **WHEN** a user clicks download on a video generated 15 days ago
- **THEN** the video file is downloaded from storage

#### Scenario: Expired video download
- **WHEN** a user tries to download a video older than 30 days
- **THEN** the system shows "보관 기간(30일)이 만료되었습니다. 영상을 다시 생성해주세요"

#### Scenario: History pagination
- **WHEN** a user has 50 generated videos and scrolls to the bottom
- **THEN** the next page of 20 items loads (infinite scroll or "더 보기" button)

### Requirement: Credit balance display
The system SHALL display the user's remaining credit balance prominently in the header/navigation. Display format: "이번 달 N/M건 사용" (M = monthly quota). The display MUST update in real-time after video generation. Low credit warning MUST appear when ≤ 1 credit remains.

#### Scenario: Credit display after generation
- **WHEN** a Free user (3 credits/month) generates a video
- **THEN** the credit display updates from "이번 달 0/3건 사용" to "이번 달 1/3건 사용"

#### Scenario: Low credit warning
- **WHEN** a user has 1 remaining credit
- **THEN** a warning badge appears: "크레딧이 1건 남았습니다"

#### Scenario: Zero credits
- **WHEN** a user has 0 remaining credits
- **THEN** the generate button is disabled with text "이번 달 크레딧을 모두 사용했습니다" and an upgrade prompt

---

### Requirement: Account deletion
The system SHALL support account deletion per GDPR and Korean 개인정보보호법. Deletion request MUST trigger a 30-day grace period before permanent deletion. During grace period, the user can reactivate by logging in. After permanent deletion, all user data, videos, and associated records MUST be removed.

#### Scenario: Account deletion request
- **WHEN** a user requests account deletion from settings
- **THEN** the account enters a 30-day grace period with confirmation message "30일 후 계정이 영구 삭제됩니다. 그 전에 로그인하면 삭제가 취소됩니다"

#### Scenario: Reactivation during grace period
- **WHEN** a user logs in during the 30-day grace period
- **THEN** the deletion is canceled and the account is fully restored

#### Scenario: Permanent deletion after grace period
- **WHEN** the 30-day grace period expires without login
- **THEN** all user data (profile, videos, subscriptions, analysis history) is permanently deleted from the database and storage
